    1. RDOQ 算法全景解析 (Algorithm Panorama)

    在深入硬件优化前，必须厘清 RDOQ 在 C-Model 中的算法本质。RDOQ 并非盲目尝试，而是一场从宏观扫描到微观计算，再到层级截断的精密“外科手术”。

    1.1 战场全貌：TU 内系数分布与“靶点”选择

    当一个 Transform Unit (TU) 经过 DCT 变换后，其能量分布具有极强的规律性：

    • 低频区（左上角）：能量高度集中，系数值极大。这里的系数对画面质量起决定性作用，几乎不可能被 RDOQ 清零。
    • 高频区（右下角）：能量稀疏，散落着大量幅值极小（量化后 Level = 1 或 2）的系数。
    RDOQ 的核心优化目标：孤立高频系数（离散高频分量）
    为何优先处理此类系数？因为在 CABAC 熵编码中，编码一个孤立的 Level=1 系数，需要消耗极高的语法开销（需要编码 sig_coeff_flag=1、坐标位置、符号位等）。它们消耗了不成比例的巨量 bits，但对画质的贡献却微乎其微。RDOQ 的核心收益，正是通过评估代价，将这些“性价比极低”的边缘系数强制量化为 0，从而换取码率的显著降低。

    1.2 微观手术：候选 LEVEL 的精准产生

    对于选定的变换系数 Ctrans，RDOQ 不会遍历所有数字，而是基于普通标量量化 (SQ) 的结果进行局部试探：

    • 首先执行普通量化：LSQ = round(Ctrans / Qstep)。
    • 随后，RDOQ 引擎通常只会产生 2 到 3 个候选 Level 参与 PK：{ LSQ, LSQ-1, 0 }。
    • 调整逻辑：它只会尝试将系数“减弱”或“抹零”，绝不会尝试“增强”（因为增强既增加误差又增加码率）。
    举个例子 (Example)：候选 Level 是怎么选的？
    假设我们有一个高频系数 Ctrans = 26，并且当前量化步长 Qstep = 10。
    1. 基准量化： 26 / 10 = 2.6，四舍五入后得到基准 LSQ = 3。
    2. 产生候选： RDOQ 引擎会选定三个候选量化值参与代价比较：Level = 3 (保持)、Level = 2 (减弱)、Level = 0 (强制量化为 0)。
    如果是像上图那样更极端的 Ctrans = 11，LSQ = 1，那么候选就只有 Level = 1 和 Level = 0 了。正是由于这种收敛机制，庞大的搜索空间被转化为极简的“二选一”或“三选一”贪婪比对。

    1.3 码率度量：从 CABAC 语法元素到 BinCost

    在评估某个候选 Level 时，Cost = Distortion + Rate。其中畸变 (D) 很容易通过差值的平方求得，但码率 (R) 则需要极其精确的估算。

    如上图所示，C-Model 的 rdoq_coeff_est() 函数会模拟真实的 CABAC 状态机更新，但不做实际的区间划分，而是查表获取理论上的“分数比特 (Fractional Bits)”。总比特消耗的计算公式为：

    Total Bits = bits(sig_coeff_flag) + bits(greater1) + bits(greater2) + bits(sign) + bits(level_rem)

    核心解密：上下文分数比特 (Fractional Bits) 与 128 级熵值查表 (Entropy LUT) 的底层逻辑

    在 CABAC 中，每个上下文模型 (Context Model) 都在不断追踪特定语法的概率状态，表现为一个 0~63 的整数状态索引 pStateIdx（代表 LPS 出现的概率），再加上 1 位的 valMPS 标志。两者组合构成了 128 个可能的上下文状态。

    前置寻址：如何找到对应的 pStateIdx？(Context Derivation)
    在查 Entropy_LUT 之前，C-Model 必须先定位当前标志位专属的概率模型，这是一个典型的数组基址+偏移的寻址过程：
    1. 基地址 (Base Offset)：不同类型的语法元素（如 sig_coeff_flag, greater1_flag）在全局的一维 Context_Array 中分配了不同的固定起址。
    2. 动态增量 (ctxInc)：系统会根据当前处理系数在空间上的特性（如：坐标距离 DC 的远近、周围局部模板内邻居系数的“非零”个数）动态推导出一个偏移量 ctxInc。
    3. 模型提取 (Fetch)：通过 Model = Context_Array[ Base_Offset + ctxInc ] 锁定唯一的上下文模型，并从中提取出该模型当前记忆的 pStateIdx 和 valMPS，最后拿着它们去查熵值表。
    为了在 RDOQ 中极速估算编码该语法的代价，必须避免极其耗时的对数（-log&sub2;(p)）和浮点运算。因此，C-Model 在初始化时，会预先通过香农熵公式计算好一张长度为 128 的 熵值查表 (Entropy LUT)。

    查表的生成算法 (C++ 伪代码解析)： 

    // 1. 计算概率衰减系数 alpha (约为 0.949)
const double alpha = pow(0.01875 / 0.5, 1.0 / 63.0);

// 2. 预生成 128 个状态的熵值代价
for (int i = 0; i < 64; i++) {
    // 根据状态索引计算 LPS (极小概率符号) 和 MPS (极大概率符号) 的实际发生概率
    double p_lps = 0.5 * pow(alpha, i);
    double p_mps = 1.0 - p_lps;
    
    // 香农熵公式: H = -log2(P)。定点放大 32768 倍 (1 bit = 32768)
    int cost_lps = (int)(-32768.0 * log2(p_lps) + 0.5);
    int cost_mps = (int)(-32768.0 * log2(p_mps) + 0.5);
    
    // 填充 LUT：假设偶数索引存储 MPS 代价，奇数存储 LPS 代价
    Entropy_LUT[i * 2]     = cost_mps;
    Entropy_LUT[i * 2 + 1] = cost_lps;
}

    在 RDOQ 执行期间，当需要计算编码某个 flag_val（0 或 1）的代价时，操作变得极其轻量化：只需执行一次位异或与数组寻址：
    bit_cost = Entropy_LUT[ (pStateIdx << 1) | (flag_val ^ valMPS) ]
    定点放大的魅力：通过预将浮点对数转化为定点整数（1 真实比特 = 32768 分数比特），原本复杂的概率计算被彻底降维。这就是为什么一个看似 1.2 bits 的代价，在硬件寄存器里其实是一个巨大的整数 39321！

    举个例子 (Example)：评估 Level = 3 的码率消耗
    假设当前评估的量化候选值是 Level = 3，那么在查表累加的过程中，它会经历如下关卡：
    • sig_coeff_flag = 1：根据该系数的 Context，查表得到分数比特 (例如 39321，约 1.2 bits)。
    • greater1_flag = 1：因为 3 > 1，查表得到对应分数比特 (例如 26214，约 0.8 bits)。
    • greater2_flag = 1：因为 3 > 2，查表得到对应分数比特 (例如 29491，约 0.9 bits)。
    • sign_flag = 1 (或0)：符号位走 Bypass 模式（等概率0.5），固定消耗 1 真实比特（即硬编码的 32768 分数比特）。
    • level_rem = 0：剩余绝对值 3 - 3 = 0，使用 Golomb-Rice 编码，消耗若干比特。
    所有这些细碎的 Fractional Bits 累加起来，就构成了评估 Level = 3 时庞大的 cabac_bits！

    图解示例：微观系数的量化判决
    Static RDOQ Decision Sandbox

    前情提要：假设有一个边缘 DCT 系数 C_trans = 15。按照普通的标量量化 (SQ)，它会被量化为 Level = 1 (反量化后 unQuant = 26)。让我们通过下面的决策树与详细的代价值拆解，看看 RDOQ 引擎是如何评估它的：

    Step 1: 评估正常量化 (Level = 1)

    • 畸变 (D): 差值 d = |15 - 26| = 11。
      D = 11² × 1024 = 123,904
    • 码率 (R): CABAC 需要编码 sig=1, gr1=0, sign=1，耗约 2.5 bits。
      R ≈ 2.5 × λ = 150,000
    • 总代价 (Cost): 123,904 + 150,000 = 273,904

    Step 2: 评估强制量化为零 (Level = 0)

    • 畸变 (D): 差值 d = |15 - 0| = 15。(误差变大)
      D = 15² × 1024 = 230,400
    • 码率 (R): CABAC 只需要编码 sig=0，耗约 0.2 bits。(码率大幅下降)
      R ≈ 0.2 × λ = 12,000
    • 总代价 (Cost): 230,400 + 12,000 = 242,400

    Step 3: 贪婪判决 (Greedy Decision)

    Cost(0) 242,400 < Cost(1) 273,904

    结论：虽然强制量化为 0 会导致像素误差 (D) 变大，但节约的编码比特 (R) 非常显著。RDOQ 引擎基于贪婪策略选择 Level = 0，成功将该系数截断为 0。这也是 RDOQ 提升压缩率的核心机制。

    1.4 宏观扫描终局：TU 级执行流程与依赖关系

    微观的系数代价值比较并非毫无章法地乱序执行。在一个完整的 Transform Unit (TU) 内部，RDOQ 遵循极其严格的逆向对角扫描 (Reverse Diagonal Scan) 与层级截断流程：

    1. 寻找末尾 (Last Position)：首先通过顺向扫描定位到频率最高的末尾非零系数，确定 RDOQ 的起点。
    2. 严格串行的逆向扫描：扫描从末尾非零系数开始，沿着对角线方向逆序向 DC (左上角) 推进。
      答疑细节：对于 1.1 节分布图中的右侧 1 (坐标 4,5) 和下方 1 (坐标 6,2)，谁先被调整？答案是：基于逆向对角线规则，更靠外侧的 (4,5) 会先被处理。并且在 C-Model 软件中，它们绝对不能同时调整，因为处理 (6,2) 时所需的 CABAC 概率模型上下文 (Context)，严重依赖于前一个系数 (4,5) 的最终调整结果。这种极度串行的时序依赖，正是硬件设计的最大梦魇。
    3. 系数组级判决 (Sub-Block Flag)：TU 被划分为多个 4x4 系数组 (CG)。当一个 4x4 CG 内部所有系数串行处理完毕后，引擎会计算“将整个 4x4 块强制量化为零”的总体代价，如果比保留内部系数的代价更低，则设置 coded_sub_block_flag = 0，从而在 CG 级别提前截断。
    4. TU 级终极判决 (Root CBF)：当逆向扫描最终到达 DC 系数 (0,0) 位置，所有系数寻优结束。引擎评估将整个 TU 强制清零的代价。如果代价最小，则触发 cbf = 0。
    计算完毕标志：
    只有当逆向扫描完整到达 (0,0) 的 DC 系数，并且完成了 系数级 $\rightarrow$ CG级 $\rightarrow$ TU级 的三层代价审核与最终锁定后，当前 TU 的 RDOQ 过程才宣告正式“计算完毕”，并将最终量化残差与 Bincost 交付给下一级流水线。

    2. 收益分布与取舍策略 (RDOQ Pruning Strategy)

    RDOQ 作为压缩率“微雕”工具，收益高度集中于边缘高频系数。工业界在架构层面必须做出极端的收益/吞吐权衡。

    核心架构抉择：弃大保小
    强制关闭大块（CU16/CU32/CU8）的 RDOQ 以满足时序吞吐限制，死保 CU4/TU4 的 RDOQ (wf4)。仅牺牲约 0.5% 的 BD-Rate，换取流水线不会因为长周期状态机陷入瘫痪。

    自然语言算法步骤 (Algorithm Steps)

    1. 尺寸侦测: 控制逻辑从上游截获当前流入 TU/CU 的像素尺寸元数据。
    2. 大块旁路剔除: 若检测到 Size > 4x4 (如 8x8、16x16)，直接封锁 RDOQ 硬件入口，迫使数据流入极简的普通标量量化 (SQ) 模块，迅速输出残差。
    3. 精英放行: 若检测到 Size == 4x4，则判定为高频收益敏感区，立刻拉高使能信号，将数据与 Context 喂入全量 RDOQ 引擎。
    4. 高频提纯: 引擎针对这些 4x4 精英块进行深度 Cost 寻优，最终压榨出极限的 Bincost 并输出纯净的高频残差。

    3. 帧内环路死锁破解 (Intra Feedback Loop Bypass)

    在 wf4 模块中，吞吐目标为 1 pix/clk（即每 16 拍处理一个 4x4 块）。但 RDOQ 会引入至少 8 拍延迟，使得总体重构反馈链路长达 24 拍，远超 16 拍预算。

    破局点：前馈重建旁路 (Fast Recon Bypass)
    为打破帧内相邻块的空间依赖链，强制预测重建像素跳过 RDOQ，走 Fast Loop 快速闭环。而 RDOQ 则在独立的 Slow Loop 中计算真实码流。

    自然语言算法步骤 (Algorithm Steps)

    1. 源头分流: 像素在完成 DCT 与简单量化 (SQ) 之后，信号兵分两路，分别进入互不干涉的独立赛道。
    2. 快环抢跑 (Fast Loop): 第一路数据完全无视后续的 RDOQ，直接冲进反量化与 IDCT。仅仅 12 拍后即刻生成“快速预测重建像素”，并在第 13 拍立刻送给隔壁紧邻的块作为 Intra 空间预测源。死锁瞬间破解。
    3. 慢环细雕 (Slow Loop): 第二路数据则带着 SQ 的结果，不慌不忙地进入 RDOQ 核心计算池，耗时 20 拍以上计算出真实的最佳 Level 和 CABAC 码流估算。
    4. 合流决断: 最终写入比特流的数据完全采纳 Slow Loop 的高精结果；Fast Loop 的粗糙数据在发挥完“打破流水线气泡”的垫脚石作用后即被丢弃。

    4. 静态上下文预生成 (Static Context Generation)

    传统的 Trellis 网格寻优存在深度的系数间因果依赖。在硬件设计中，必须采用“局部独立近似”来替换“全局网格搜索”，为彻底打平流水线铺平道路。

    自然语言算法步骤 (Algorithm Steps)

    1. 静态快照剥离: 抛弃原本动态更新上下文的做法，改为在第 1 拍利用初步 SQ 的结果，一次性暴力预生成 16 个系数的 CABAC Context 静态快照。这彻底切除了系数计算之间的时序依赖链。
    2. 搜索空间极简压缩: 舍弃了从 0 一直搜索到最优 Level 的传统庞大循环，硬件判定器强行锁定只有原始 Q 和减弱一档的 Q-1 两个候选目标参与角逐。
    3. 并行兵团展开: 点亮 16 个完全独立的物理计算单元 (Compute Unit)。这 16 个单元在同一时钟周期内，各自抱着自己的 Context 快照，疯狂且独立地计算自己所属系数的 Q Cost 和 Q-1 Cost。
    4. 决出局部霸主: 16 个单元内部的比较器瞬间各自决出 Cost 最小的优胜 Level。最终通过总线拼合，形成当前 4x4 块的伪全局最优解。

    5. 终极吞吐利器：Two-Stage Fast RDOQ Pruning

    为了满足严苛的 4K/8K 帧率，单纯在底层进行流水线化仍显不足，必须从宏观算法上源头把控，控制 RDOQ 模块的绝对启动频次。

    两级 Candidate 剪枝过滤：
    前级采用标量量化 (SQ) 与 CABAC 初估，选出 Top-2 Best Candidates。仅将这 2 个 Candidate 扔入深度 RDOQ 流水线。牺牲极小 BD-Rate，削减 70% 的面积与时间开销，完美闭环 16 clk 预算！

    自然语言算法步骤 (Algorithm Steps)

    1. 海选起跑线: 帧内预测模块筛选出的 16 个潜在最优模式 (Candidates) 汹涌涌入流水线。
    2. 廉价粗筛阵列: 对于这 16 个候选者，门禁系统强行禁止它们触碰昂贵的 RDOQ 引擎，而是让它们全部只经过廉价的普通 SQ 量化，并结合简易查表估算出一个极其粗糙的 Cost。
    3. 末位残酷淘汰: 硬件冒泡排序树接收这 16 个粗糙 Cost 并进行火速排序，当场无情抹杀排名靠后的 14 个选项，只留下金字塔尖的 Top-2 精英。
    4. 精英极深造: 此时，只有这历经千辛万苦幸存的 2 个 Elite Candidates，才被获准正式踏入极其吃面积与功耗的 4-Unit 深度 RDOQ 优化阵列。吞吐量从而被奇迹般地压制在了物理预算极限之内。

    6. 亮色度分治策略 (Luma-Chroma RDOQ Bypass)

    在实际硬件流水线中，针对亮色度采取非对称的量化策略，以追求极致的性价比与吞吐率。这是一种完全符合标准语法且 100% 保证编解码一致性（Mismatch Free）的经典工程权衡。

    核心优化：Luma 开启 RDOQ，Chroma 关闭 RDOQ
    由于人眼对亮度细节远比色度敏感，RDOQ 带来的压缩收益绝大部分集中在 Luma (亮度) 分量。强迫 Chroma (色度) 旁路 RDOQ，仅执行基础的标量量化 (SQ)，可在几乎不影响整体 BD-Rate 的前提下，节省可观的计算周期与面积开销。

    自然语言算法步骤 (Algorithm Steps)

    1. 分量侦测: 流水线控制端根据当前 TU 的颜色通道元数据，区分 Luma (Y) 与 Chroma (Cb/Cr)。
    2. 色度快速旁路 (Chroma Fast-Path): 若为色度通道，强制封锁 RDOQ 硬件入口使能，数据仅流过廉价的普通标量量化 (SQ) 模块，快速闭环并输出残差。
    3. 亮度深度精雕 (Luma RDOQ-Path): 若为亮度通道（且符合 4x4 等精英尺寸），则获准进入完整的 RDOQ 深度优化寻优阵列，以压榨极限的视觉与码流收益。
